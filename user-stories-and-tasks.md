
# PowerShare – User Stories and Tasks

## 1. Introduction

PowerShare is a pay-as-you-go portable energy rental service for micro-entrepreneurs in Khayelitsha and Mitchells Plain. It aims to help small businesses continue essential operations during power outages by providing portable lithium power stations.

User stories help the team understand the needs of the people who may use the service.

## 2. User Stories

### User Story 1: Find Available Power Stations

**As a** small-business owner,  
**I want** to view available portable power stations,  
**so that** I can find a suitable option for my business during an outage.

**Acceptance Criteria:**
- The user can view available power station options.
- Each option displays relevant information.
- The user can identify an option suitable for their needs.

**Tasks:**
- Identify the information users need about each power station.
- Design a page or process for viewing available options.
- Test whether users can understand the available options.

### User Story 2: Rent a Power Station

**As a** micro-entrepreneur,  
**I want** to rent a power station using a pay-as-you-go option,  
**so that** I can access backup power without purchasing expensive equipment.

**Acceptance Criteria:**
- The rental process explains the available option and its cost.
- The user can submit a rental request.
- The user receives confirmation or clear feedback about the request.

**Tasks:**
- Define the rental information required from a user.
- Design the rental request process.
- Validate submitted information.
- Test the rental process.

### User Story 3: Understand Rental Costs

**As a** small-business owner,  
**I want** to understand the rental charges before proceeding,  
**so that** I can make an affordable decision for my business.

**Acceptance Criteria:**
- Rental charges are clearly communicated.
- The user can review the applicable cost before confirming a request.
- Any applicable terms are explained clearly.

**Tasks:**
- Identify the rental pricing information that must be displayed.
- Design a clear way to present the costs.
- Test whether the pricing information is easy to understand.

### User Story 4: Check Rental Request Status

**As a** customer,  
**I want** to check the status of my rental request,  
**so that** I know whether my request has been received and processed.

**Acceptance Criteria:**
- The system provides understandable status information.
- The user receives feedback after submitting a request.
- Status information is presented clearly.

**Tasks:**
- Identify the possible rental request statuses.
- Design how status information will be displayed.
- Test the status updates and feedback.

### User Story 5: Manage Power Station Availability

**As a** PowerShare service administrator,  
**I want** to manage power station availability and rental requests,  
**so that** I can keep track of equipment and customer requests.

**Acceptance Criteria:**
- The administrator can view relevant rental requests.
- Equipment availability can be updated.
- Changes are reflected accurately in the system.

**Tasks:**
- Identify the information an administrator needs.
- Design the equipment and request management process.
- Test updates to availability and rental records.

## 3. Prioritisation

The user stories should be prioritised according to their importance to the core rental service.

| Priority | User Story | Reason |
|---|---|---|
| High | View available power stations | Users need to identify available options. |
| High | Rent a power station | This supports the main service. |
| High | Understand rental costs | Users need to make informed affordability decisions. |
| Medium | Check request status | Helps users understand progress. |
| Medium | Manage availability | Supports service administration. |

## 5. Personal Reflection

Writing user stories helps me understand how to describe system requirements from the user's point of view. For PowerShare, it is important to consider the challenges faced by small-business owners when power outages interrupt their work.

I learned that acceptance criteria make requirements clearer because they describe what should happen for a story to be considered complete. Breaking stories into smaller tasks also helps the team organise the work and track progress.

## 6. Conclusion

The user stories and tasks translate PowerShare's main purpose into user needs and practical development activities. They give the team a clearer starting point for planning the product backlog and deciding which features should be developed first.
